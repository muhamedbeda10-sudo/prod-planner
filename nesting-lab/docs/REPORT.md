## 2. المدعوم فعلًا

**قراءة DXF (ASCII فقط؛ Binary DXF يُرفض برسالة واضحة):** HEADER (`$ACADVER`، `$INSUNITS`،
`$EXTMIN/$EXTMAX`)، جدول LAYER (ويُبلّغ عن Layers مستخدمة وغير معرّفة)، BLOCKS + INSERT (إزاحة،
دوران، تكبير منتظم، صفوف/أعمدة؛ التكبير غير المنتظم للأقواس يُرفض ويُبلَّغ)، الكيانات:
LINE، LWPOLYLINE (مع bulges والإغلاق)، POLYLINE/VERTEX ثنائي البعد، CIRCLE، ARC.
TEXT/MTEXT/DIMENSION/POINT/HATCH… تُحسب "annotation" ولا تُقص. ELLIPSE وSPLINE وأي نوع
مجهول: **غير مدعوم** ويُعرض بالعدد والـ Layer (لا يُسقط بصمت). الإحداثيات ثلاثية البعد
والـ extrusion غير +Z تُبلَّغ.

**الهندسة:** الأقواس تبقى أقواسًا بالضبط (bulge ↔ arc بلا فقد)؛ ربط الأجزاء بتسامح معلن
(0.01 مم افتراضيًا، ويُبلّغ عن أكبر فجوة أُغلقت)؛ تقسيم عند التقاطعات والتقاء T والتداخل
الخطي (common-line cut)؛ دمج المكررات؛ استخراج الأوجه المغلقة (planar face extraction) →
قطع بحدود خارجية وثقوب وعمق احتواء؛ الخطوط المعلّقة (lead-ins/إنشائية) تُبلَّغ "open
geometry" ولا تدخل في أي قطعة؛ كشف حدود اللوح (مستطيل محاذٍ يطابق الامتدادات ويحوي قطعًا)
وهو ليس قطعة؛ تجميع القطع المتطابقة بمطابقة صلبة دقيقة (0.02 مم) مع إبقاء **المعكوسة** نوعًا
منفصلًا مع الإشارة "mirror of". علامات (Layer بدور mark) تُلحق بالقطعة الحاوية وتُصدَّر على
Layer `MARK`.

**المحرك:** True-shape فعلي: no-fit polygons عبر تفكيك محدب (ear clipping + Hertel–Mehlhorn)
ومجاميع Minkowski محدبة ثم union بـ Clipper؛ ترتيب القطع ×3 × هدف الوضع ×3 = 6 استراتيجيات
حتمية، تُقارن ويُختار الأفضل بمعيار معلن (أقل عدد ألواح، ثم آخر لوح الأقل امتلاءً = أكبر
بقية)؛ ألواح متعددة؛ مخزون ألواح محدود؛ دوران مسموح به (أي قائمة زوايا)؛ mirror اختياري؛
مناطق محظورة (clamps)؛ أولوية لكل قطعة؛ ميزانية زمن. القطع تُنست في التجاويف وداخل الفتحات
المفتوحة (ثبت بالاختبار: شكلان L يتشابكان على لوح لا يتسع لمستطيليهما).

**الفاحص المستقل (`verify.ts`):** لا يشارك كودًا مع Clipper/NFP؛ يفحص بمضلعات تحيط بالأقواس
(سهم 0.01 مم): عدم تداخل، المسافة بين القطع ≥ spacing، داخل الحدود ≥ margin، بعيد عن المناطق
المحظورة، الكميات كاملة، وأن المحيط الموضوع مطابق للمصدر (مساحة ومحيط). التسامح 0.02 مم معلن
في التقرير.

**التصدير:** DXF R2000 (AC1015) بـ `$INSUNITS=4` صراحة، أصل الإحداثيات أسفل يسار اللوح،
Layers: `SHEET`/`CUT_INNER`/`CUT_OUTER`/`MARK`/`LABEL`، الثقوب قبل الحدود الخارجية، أقواس
بـ bulge ودوائر CIRCLE بلا تكسير. **التحقق:** إعادة القراءة بنفس القارئ ومقارنة كل قطعة
(bbox/مساحة/محيط/عدد ثقوب) مع اختبار يثبت أن الفحص يكتشف محيطًا ناقصًا أو ثقبًا مفقودًا،
وقراءة مستقلة بـ `dxf-parser` (JS) داخل الاختبارات، وبـ **ezdxf 1.4.5** (Python، قارئ صارم
+ audit) على كل ملفات العينتين: السكربت `scripts/ezdxf-audit.py` والسجل
`out/samples/ezdxf-audit.txt` (0 أخطاء، 0 إصلاحات لكل الملفات). SVG بأقواس دقيقة،
CSV (UTF-8 BOM)، JSON report كامل قابل لإعادة الإنتاج (settings، engine version، كل placement،
hash لهندسة كل قطعة).

## 3. غير المدعوم / القيود (بصراحة)

- **برامج تشغيل المكن (NC/G-code/صيغ خاصة): غير مهيأة.** لا توجد مواصفة كنترول ولا عينة
  مرجعية لأي ليزر (Bodor/GF/Yawy) ولا للتخريم. الـ registry يعرضها "not configured" مع
  المطلوب بالضبط. لم يُغيَّر امتداد أي ملف لادعاء دعم.
- ملفات **Binary DXF**، و**SPLINE/ELLIPSE** (تُبلَّغ ولا تُقرّب)، وDXF ثلاثي البعد الحقيقي.
- الألواح **مستطيلة** فقط؛ البواقي (remnants) غير مستطيلة لم تُنفَّذ (يمكن تمثيل بقية مستطيلة
  كلوح أصغر).
- **لا تعويض kerf** (مقصود: يُطبَّق في برنامج الماكينة مرة واحدة)، ولا lead-in/lead-out،
  ولا ترتيب مسار القص بين القطع، ولا micro-joints.
- **اتجاه الحبيبات** يُعبَّر عنه بتقييد الدورانات (0/180) فقط.
- النتيجة **تقريبية جيدة وليست مثلى عالميًا** (greedy bottom-left over NFPs). لا تحسين
  لاحق (local search/GA) في هذه النسخة.
- **تحفّظ هندسي:** مضلعات النيستينج تحيط بالأقواس (0.3 مم) وتُبسَّط (0.05 مم) ثم تُوسَّع
  بتعويض التبسيط + تسامح التدوير (0.1 مم)؛ لذلك لا تقترب قطعتان أقل من spacing أبدًا، لكن قد
  تبعدان حتى **0.3 مم** أكثر من اللازم. القطع التي تحتاج اللوح بالمليمتر الأخير قد لا تدخل.
- تمييز **الفضلات عن القطع** في ملفات common-line cut غير حاسم آليًا: كل وجه مغلق يسقط من
  اللوح يُعرض قطعة مع علامات مراجعة (مخطط غير منتظم، صغير، محاط بالكامل بأضلاع مشتركة)؛
  القرار للمستخدم.
- التعديل اليدوي (سحب/تدوير قطعة في المعاينة) غير مُنفَّذ؛ المعاينة zoom/pan وhover فقط.
- حدود: 5000 قطعة لكل تشغيل، 20000 ضلع للقطعة، 500 لوح، ميزانية زمن افتراضية 30 ث (الاستراتيجية
  الأولى تكمل دائمًا). حدود ضد الملفات العدائية: 2 مليون ضلع بعد فك الـ Blocks، 10000 نسخة لكل
  INSERT، نصف قطر ≤ 10^7 مم، 20 مليون زوج تقاطع؛ تجاوزها يُرفض برسالة واضحة.
- **تحليل الملف يعمل في الـ main thread** للمتصفح (مللي ثوانٍ للملفات العادية)؛ النيستينج فقط في
  Web Worker. ملف ضخم يبطئ التبويب الأول لحظيًا بدل أن يُلغى.
- Layers بأسماء مثل `constructor` أو Blocks باسم `__proto__` تُعامل كأي اسم (خرائط بلا prototype).

## 4. دقة الهندسة

- الأقواس والدوائر تُحفظ بلا فقد في كل المراحل (القراءة، الاستخراج، التحويل، التصدير).
- إعادة قراءة التصدير: الإحداثيات تُكتب بست خانات عشرية → Δ bbox ≤ 1e-6 مم، Δ مساحة ≤ 1e-4 مم²
  لقطعة 6000 مم² (أقصى ما قيس على العينتين: 3.3e-5 مم²).
- Clipper يعمل بأعداد صحيحة بمقياس 1000 (ميكرون).
- تسامح ربط الأجزاء 0.01 مم؛ مطابقة القطع المتطابقة 0.02 مم؛ الفاحص 0.02 مم مسافة / 0.01 مم سهم.
- فحص ezdxf الصارم: 0 أخطاء/0 إصلاحات لملفات الألواح والقطع المصدَّرة.

## 6. أدوات المراجعة المستخدمة وما طلع منها

- `npm run typecheck` (strict)، `npm run test:run` (91 اختبارًا)، `npm run build`.
- Playwright + Chromium: تشغيل الواجهة من أول رفع الملفين حتى بناء التصدير وإعادة القراءة،
  ولقطات على 390 px (بدون scroll أفقي)، 1366 px، 1800 px، وفي الوضع الغامق (اللقطات ليست في
  الريبو؛ السكربت تشغيل يدوي).
- ezdxf (Python) كقارئ مستقل (`scripts/ezdxf-audit.py` + `out/samples/ezdxf-audit.txt`)،
  وdxf-parser (JS) داخل الاختبارات.
- مراجعات الكود (CLAUDE.md §6): `code-review`، و`review-council` (correctness، security،
  architecture، test-evidence، policy-boundary)، و`a11y-enforcer`. أهم ما طلع واتصلّح:
  - **صحة:** أقواس الـ bulge داخل INSERT معكوس كانت تُقلب حول وترها (قوس 270° بدل 90°)؛
    الدوائر الكاملة بعد دوران 90/180/270 كانت تُرسم غلط في SVG؛ تحويط الأقواس المقعرة كان
    يدخل في المعدن حتى 0.3 مم؛ الكيانات ذات extrusion −Z (أمر MIRROR في AutoCAD) كانت
    تُسقط بدل تحويلها إلى إحداثيات العالم؛ MINSERT بزاوية؛ مطابقة القطع الدائرية المعكوسة.
  - **أمان/متانة:** INSERT بمصفوفة 10^12 نسخة أو Block يستدعي نفسه كان يعلّق المتصفح؛ نصف
    قطر ضخم كان يصنع حلقة لا نهائية؛ خط إنشائي طويل كان يحوّل شبكة التقاطعات إلى O(N²)؛
    حقن معادلات في CSV من اسم الملف؛ أسماء Layers بأسماء prototype.
  - **بنية:** تعريف معنى الـ placement في مكان واحد (`nesting/placement.ts`)؛ بانٍ واحد
    للقطع يستخدمه الـ UI والـ CLI (`engine/parts.ts`)؛ خط تصدير واحد بلا I/O
    (`export/exportRun.ts`)؛ عقد ترتيب المكن بنفس شكل `MachineRuleLike` في التطبيق
    (minKva/maxKva)؛ مخرجات العينات حتمية (run ids وتواريخ ثابتة).
  - **أدلة الاختبار:** اختبارات سلبية للفاحص (spacing، حدود، مناطق محظورة، كميات، احتواء)،
    ولإعادة القراءة (محيط ناقص/ثقب مفقود)، ولميزانية الزمن بساعة مزيفة، ولحدود الملفات العدائية.
  - **إتاحة:** أسماء لأزرار الزوم، تحكم بلوحة المفاتيح في المعاينة، إدخال الملف قابل للوصول،
    مناطق live للحالة والأخطاء، تباين زر الـ primary في الوضع الغامق (كان 2.7:1 → 6.9:1).
- لم أستخدم `design:design-system` ولا `frontend-design` لأن النموذج خارج design system
  التطبيق عمدًا (CSS مستقل بـ tokens للفاتح والغامق)؛ عند الدمج تُستبدل الواجهة بمكونات التطبيق.

## 7. ملاحظة مهمة قبل أي دمج: إعدادات الريبو الأصلي

`tsconfig.json` و`eslint.config.mjs` في جذر الريبو يشملان كل `**/*.ts(x)`، فأي `npm run typecheck`
أو `npm run lint` أو `next build` من الجذر سيشمل مجلد `nesting-lab/`. لم ألمس ملفات التطبيق
(تعليماتك لهذه المرحلة). حرصت أن يكون كود النموذج قابلًا للفحص بإعدادات الجذر (لا import لحزم غير
موجودة في الجذر: `clipper-lib` بتعريف محلي، `dxf-parser` عبر `createRequire`، CSS عبر `<link>`)،
لكن لم أستطع تشغيل فحوص الجذر هنا (`npm ci` فشل: الـ proxy يرفض تنزيل `xlsx` من cdn.sheetjs.com).
**قبل الدمج** القرار لك: إما استثناء المجلد في الجذر (`"exclude": ["node_modules", "nesting-lab"]` في
`tsconfig.json` و`"nesting-lab/**"` في `globalIgnores` بـ `eslint.config.mjs`، و`nesting-lab/**` في
`outputFileTracingExcludes` بـ `next.config.ts` حتى لا تُرفع العينات مع كل function)، أو نقل المحرك
إلى `lib/domain/nesting` كخطوة الدمج الأولى. الـ CI الحالي لا يشغّل اختبارات النموذج (91) — تُشغَّل
محليًا بـ `npm run test:run` داخل `nesting-lab/`.
